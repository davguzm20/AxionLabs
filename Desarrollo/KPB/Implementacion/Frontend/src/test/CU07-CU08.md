# CU07 y CU08: alcance del frontend con mocks

Se contrastan `KPB-CU07.docx`, `KPB-CU08.docx`, RQ16–RQ20 y RNF012–RNF015.
No se utiliza ni se verifica el backend; PostgreSQL y el envío real de correo están fuera de este alcance.

## Trazabilidad

| Requisito | Implementación y comprobación |
| --- | --- |
| CU07/RQ16: configurar topes por categoría | Catálogo completo de gastos, categorías sin tope, creación de las opciones predefinidas faltantes y edición conjunta de monto y umbrales. |
| CU07/RQ17: periodos | Semanal desde el lunes, mensual y personalizado recurrente; fechas civiles de Lima, renovación y recálculo con movimientos reales del mock. |
| CU07: confirmación | Mensaje de éxito en el listado al crear y al editar. |
| CU07 EX1–EX3 | Rutas protegidas, manejador de sesión expirada montado en `App`, validación de monto y recuperación ante categoría rechazada. |
| CU08/RQ18: umbrales | Predefinidos y personalizados del 1% al 100%, múltiples porcentajes únicos vinculados al presupuesto por ID. |
| CU08/RQ19: monitoreo | Consumo en céntimos según categoría, moneda y periodo; incluye gastos previos y reclasificados; ignora ingresos y presupuestos inactivos. |
| CU08/RQ20: aviso | Evento `alert.created` consumido por el cliente real; bandeja y contador compartidos; recuperación por consulta cada 4 s si SSE no está disponible. |
| CU08 EX2 | Sobregiro de prioridad alta incluso sin umbral explícito del 100%; saldo, porcentaje y accesos a movimientos y presupuestos. |
| Registro y exactitud | Movimientos, eventos, fecha/hora, porcentajes y lectura persistidos en almacenamiento local de demostración; deduplicación por presupuesto, periodo y umbral. |

## Pruebas

- `mocks/budgetLifecycle.test.ts`: consumo, validaciones, guardado sin cambios parciales, recarga, periodos, múltiples umbrales y sobregiros.
- `mocks/budgetPeriods.test.ts`: límites de semana/mes en Lima, año bisiesto y periodos personalizados.
- `test/cu07Cu08.integration.test.tsx`: pantallas y enrutador de `App`, con los manejadores generales de MSW. Solo se sustituyen respuestas para probar errores y caídas de SSE.
- `features/chat/components/AlertCard.test.tsx`: porcentaje, saldo y moneda visibles en el chat.
- `mocks/enableMocking.test.ts`: arranque de MSW en desarrollo y exclusión en producción.

Desde el directorio del frontend:

```sh
npm test
npm run lint
npm run build
```

Las pruebas verifican entrega por SSE sin refresco manual antes de 5 s y recuperación sin SSE. No sustituyen una certificación de rendimiento bajo carga ni una prueba visual en dispositivos reales.

MSW se inicia únicamente mediante el servidor de Node de Vitest. La aplicación del navegador, también en desarrollo, consume la API configurada y no registra un Service Worker. Los datos guardados son solo de demostración, no almacenamiento seguro de información financiera real.
