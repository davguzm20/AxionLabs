# Pruebas de frontend de CU03 — registro por nota de voz

## Alcance

Se prueban los componentes y servicios actuales del frontend con Vitest, Testing Library, jsdom y MSW. No se requiere backend, correo, micrófono real ni servicios externos. No se modifica lógica funcional ni los mocks de desarrollo de la aplicación.

Se conserva el contrato implementado: `POST /transactions/voice` genera una vista previa y `POST /transactions/voice/confirm` confirma los datos. No se sustituyen estas rutas por las del diseño (`/transcriptions`, `/extractions/text` y `/transactions`). Estos tests no certifican integración con backend.

Referencias: `Desarrollo/KPB/Analisis/Casos de Uso/KPB-CU03.docx` y `Desarrollo/KPB/Diseño/{KPB-API.docx,KPB-PP.docx}`. Los límites de 5 MB y 60 segundos corresponden al frontend actual, no a una medición del reconocimiento de voz.

## Ejecución

Desde `Desarrollo/KPB/Implementacion/Frontend`, en Bash/Git Bash:

```bash
NODE_OPTIONS=--no-experimental-webstorage npm test -- src/features/chat/voice src/features/chat/ChatPage.voice.test.tsx --maxWorkers=2
npm run lint
npm run build
```

En PowerShell, definir `$env:NODE_OPTIONS = '--no-experimental-webstorage'` antes de ejecutar `npm test`. La opción evita que Web Storage nativo de Node 26 interfiera con localStorage de jsdom.

Para comprobar regresiones de CU01/CU02 junto con CU03:

```bash
NODE_OPTIONS=--no-experimental-webstorage npm test -- src/features/auth src/features/chat --maxWorkers=2
```

Suite completa con orden aleatorio reproducible:

```bash
NODE_OPTIONS=--no-experimental-webstorage npm test -- --maxWorkers=2 --sequence.shuffle --sequence.seed=20261108
```

La suite conserva cuatro regresiones funcionales como pruebas activas. Las correcciones descritas abajo hacen que se ejecuten y pasen; no se aumentaron timeouts, no se omitieron casos ni se usó `it.fails` para convertirlas en aprobadas.

## Regresiones cubiertas y corregidas

| Prueba | Comportamiento esperado | Corrección aplicada |
|---|---|---|
| C03-DEF-01 | Reintentar el mismo guardado con el mismo borrador conserva `Idempotency-Key`. | `voiceService.ts` reutiliza la clave por preview y borrador; `ChatPage` pasa la clave que conserva para el reintento. |
| C03-DEF-02 | Al expirar la sesión se elimina de `localStorage` el chat que contiene datos privados. | El efecto de persistencia verifica que exista `access_token`; si no existe, elimina el chat y no lo vuelve a escribir. |
| C03-DEF-03 | Un monto nulo, vacío, no numérico o no positivo mantiene deshabilitado **Aceptar**. | `TransactionPreviewCard.tsx` valida el formato y que el monto sea finito y mayor que cero. |
| C03-DEF-04 | Una alerta `high` prevalece sobre una normal, independientemente del umbral de esta. | `ChatPage.highestPriorityAlert` compara primero la prioridad y, dentro del mismo nivel, el umbral. |

Las cuatro aserciones siguen como pruebas normales. La categoría inactiva compartida con CU02 tiene su regresión en `components/TransactionPreviewCard.test.tsx`; no se duplica aquí.

## Aislamiento y compatibilidad del entorno

- Se limpia localStorage y el estado simulado mediante `resetFrontendState` antes de cada prueba HTTP; las cachés de React Query son independientes.
- Los handlers locales se restauran después de cada prueba. Las solicitudes sin handler siguen siendo errores según la configuración global.
- `MediaRecorder`, `Audio`, permisos, URLs temporales y pistas de micrófono son sustitutos controlados y se restauran al terminar. Solo los tests del contador usan temporizadores falsos.
- En los tests HTTP, `FormData`, `Blob` y `File` pertenecen a la misma implementación nativa que `fetch` de Node: su mezcla con los objetos de jsdom no serializa multipart correctamente en Node 26. La adaptación es local y reversible; no cambia configuración ni dependencias. MSW sigue recibiendo y analizando una petición multipart real, sin falsificar sus cabeceras.

## Resultados

Ejecución focalizada después de corregir las cuatro regresiones: **71 casos aprobados, cero fallidos**, sin omisiones ni errores no capturados. Las 30 pruebas de `VoiceRecorder`, las 11 de `voiceService` y las 30 de `ChatPage.voice` pasaron.

`npm run lint`, `npx tsc -b` y `npm run build` correctos. La compilación avisa sobre anotaciones de Zod y tamaño del paquete; no impiden generar el build.

Antes de añadir CU03 se ejecutó la suite completa: **159 aprobados, ocho fallidos y dos errores no capturados** (167 casos). Los ocho fallos previos pertenecen a historial, notificaciones y los mocks de saldos/notificaciones; no se modificaron esos archivos. Los cinco casos existentes con `it.fails` de CU01/CU02 siguen incluidos en los aprobados de Vitest y no se consideran defectos resueltos.

Después de añadir CU03, la suite completa con orden aleatorio y semilla `20261108` ejecutó **238 casos: 226 aprobados y 12 fallidos**, más los mismos dos errores no capturados del historial. Los 12 fallos son los ocho preexistentes y los cuatro documentados de CU03. Las 151 pruebas anteriores de CU01/CU02 mantienen su resultado, incluidos sus cinco fallos esperados; no aparecieron regresiones adicionales.

## Fuera de alcance

No se verifican precisión de transcripción del 90 %, procesamiento real en 20 s, acceso físico al micrófono, persistencia o deduplicación de un backend, ni envío real de alertas. Se comprueba que el frontend presenta y transporta correctamente las respuestas simuladas, y que no persiste el archivo de audio en el chat. No se declara un porcentaje de cobertura de código ni cumplimiento completo del CU03.
